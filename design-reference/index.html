04Development philosophy

How I think about building for the web.

  1. 01

    Reusable by default

    I build and centralize components and custom hooks, so consistency comes from the codebase itself, not from good intentions.

  2. 02

    Fast by design

    Code splitting, memoization, lazy loading and lean state management are habits from the first commit, not a cleanup at the end.

  3. 03

    Proven, not assumed

    Components and hooks get unit tests. Interfaces get cross-browser checks. Code gets reviewed, with AI as a second pair of eyes and a human making the call.

  4. 04

    Clear across the stack

    I trace data end to end, from REST endpoints to the pixel, and I write things down so the next developer can pick it up quickly.

08How I build products

A repeatable path from brief to shipped feature.

  2. 02
